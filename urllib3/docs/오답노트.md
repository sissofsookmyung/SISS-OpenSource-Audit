## 🔍 변경 요약

### 1. 기본 헤더 제거 목록 수정

**파일:** `src/urllib3/util/retry.py`

```diff
-DEFAULT_REMOVE_HEADERS_ON_REDIRECT = frozenset(["Cookie", "Authorization"])
+DEFAULT_REMOVE_HEADERS_ON_REDIRECT = frozenset(
+    ["Cookie", "Authorization", "Proxy-Authorization"]
+)
```

기존에는 리다이렉트 시 기본적으로 제거할 헤더에 `Cookie`와 `Authorization`만 포함되어 있었다. 이번 패치에서는 `Proxy-Authorization`을 추가하여, 교차 호스트 리다이렉트 시 프록시 인증 정보가 의도하지 않은 목적지로 전달될 위험을 줄였다.

### 2. 기본 설정 단위 테스트 보강

**파일:** `test/test_retry.py`

```python
retry = Retry()
assert retry.remove_headers_on_redirect == {
    "authorization",
    "proxy-authorization",
    "cookie",
}
```

`Retry` 객체의 기본 제거 대상 목록에 세 가지 헤더가 모두 포함되는지 검사한다. 이 테스트는 **설정값**을 확인하며 실제 네트워크 요청의 헤더 제거 여부를 직접 검증하지는 않는다.

### 3. 실제 리다이렉트 통합 테스트 보강

**파일:** `test/with_dummyserver/test_poolmanager.py`

`test_redirect_cross_host_remove_headers` 테스트의 최초 요청에 `Proxy-Authorization`을 추가했다.

```python
headers={
    "Authorization": "foo",
    "Proxy-Authorization": "bar",
    "Cookie": "foo=bar",
}
```

테스트는 다른 호스트의 `/headers` 경로로 리다이렉트한 뒤 최종 서버가 수신한 헤더를 확인한다.

```python
assert r.status == 200
data = r.json()
assert "Authorization" not in data
assert "Proxy-Authorization" not in data
assert "Cookie" not in data
```

또한 소문자 헤더(`authorization`, `proxy-authorization`, `cookie`)로 요청한 경우에도 해당 헤더가 제거되는지 확인한다. HTTP 헤더 이름은 대소문자를 구별하지 않으므로 이 검사는 의미가 있다.

|------|------------|------------|--------------|
| 리다이렉트 기본 제거 헤더 | `Cookie`, `Authorization` | 기존 목록에 `Proxy-Authorization` 추가 | 프록시 인증 정보가 다른 호스트로 전달될 위험 감소 |
| 기본 설정 단위 테스트 | 두 헤더만 확인 | 세 헤더 확인 | 기본 보안 설정의 회귀 방지 |

### 취약점 원인 및 영향

`Proxy-Authorization` 헤더는 프록시 서버 인증에 사용하는 정보를 담을 수 있다. 특정 HTTP 리다이렉트 처리 경로에서 이 헤더가 제거되지 않으면, 원래 의도한 대상이 아닌 호스트로 인증 정보가 전달될 가능성이 있다. 이는 민감한 인증 정보의 노출 위험으로 이어진다.

이번 수정의 핵심은 **리다이렉트 시 기본적으로 제거할 헤더 목록에 `Proxy-Authorization`을 추가한 것**이다. 다만 모든 프록시 구성, 모든 리다이렉트 유형, 사용자가 기본 제거 목록을 재정의한 상황까지 동일한 보호가 적용된다고 일반화해서는 안 된다.
