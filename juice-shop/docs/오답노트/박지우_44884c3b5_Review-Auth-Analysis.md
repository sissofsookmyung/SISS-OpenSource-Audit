이번 커밋은 OWASP Juice Shop의 상품 리뷰 수정 기능에서 로그인 상태를 확인하는 조건을 개선한 변경이다. 기존에는 리뷰 작성자가 익명인지 확인했지만, 변경 후에는 현재 사용자의 로그인 상태를 직접 확인하도록 수정되었다.

## 2. 변경 내용 및 원인

### A. 어떤 문제가 있었는가?

기존 리뷰 수정 버튼은 리뷰 작성자가 `Anonymous`가 아니면서 현재 사용자의 작성자 정보와 일치하는 경우 표시되었다.

그러나 작성자가 익명이 아니라는 조건만으로는 사용자의 실제 로그인 상태를 확인할 수 없다. 따라서 리뷰 수정 버튼을 표시할 때 로그인 여부를 명확하게 검사하도록 조건이 변경되었다.

### B. 어떻게 수정되었는가?

**① 리뷰 수정 버튼 표시 조건 변경**

```diff
- @if (review.author !== 'Anonymous' && review.author === author) {
+ @if (isLoggedIn() && review.author === author) {
```

기존의 익명 작성자 검사 대신 `isLoggedIn()`을 사용하도록 수정되었다.

변경 후에는 로그인 토큰이 존재하고 리뷰 작성자가 현재 사용자의 작성자 정보와 일치해야 수정 버튼이 표시된다.

**② 리뷰 제출 버튼의 유효성 검사 조건 변경**

```diff
- [disabled]="reviewForm.message().invalid() || !reviewModel().message.trim()"
+ [disabled]="reviewForm.message().invalid()"
```

기존에는 폼 유효성 검사와 공백 제거 후 빈 문자열인지 확인하는 조건을 함께 사용했다.

변경 후에는 `reviewForm.message().invalid()`만 사용하도록 단순화되었다.

관련 PR #3716에서는 Angular Signal Forms로 전환하면서 공백만 입력한 리뷰를 거부하도록 입력값 검증을 개선했다고 설명한다. 다만 이번 커밋 자체에서는 HTML 템플릿의 버튼 비활성화 조건만 변경되었다.

## 3. 보안 관점 분석

| 항목 | 이전 버전 | 변경 버전 | 보안적 의미 |
|---|---|---|---|
| 로그인 확인 | 익명 작성자 여부 검사 | `isLoggedIn()` 사용 | 로그인 상태를 버튼 표시 조건에 명시 |
| 작성자 확인 | 리뷰 작성자 비교 | 동일하게 유지 | 작성자 일치 조건 유지 |
| 제출 버튼 | 폼 유효성 및 공백 검사 | 폼 유효성 검사만 사용 | 입력값 검증 로직 단순화 |
| 서버 권한 검증 | 해당 커밋에서 확인되지 않음 | 변경 사항 없음 | 서버 접근 제어 개선 여부는 별도 검증 필요 |

### 로그인 상태 확인 함수

`product-details.component.ts`에서 `isLoggedIn()` 함수의 구현을 확인했다.

```typescript
isLoggedIn () {
  return localStorage.getItem('token')
}
```

이 함수는 브라우저의 `localStorage`에 저장된 `token` 값을 반환한다.

토큰이 없으면 `null`을 반환하므로 버튼 표시 조건이 거짓이 된다. 반면 비어 있지 않은 토큰 문자열이 존재하면 참으로 평가될 수 있다.

다만 토큰의 유효성이나 만료 여부까지 검증하는 것은 아니다.

### 보안적 의미 및 한계

이번 변경은 리뷰 수정 버튼의 표시 조건에 로그인 여부를 추가했다는 점에서 의미가 있다.

그러나 수정된 코드는 Angular 프론트엔드 템플릿이므로 서버의 접근 제어가 강화되었다고 볼 수는 없다.

클라이언트에서 버튼을 숨기더라도 서버가 권한 없는 수정 요청을 허용한다면 접근 제어 문제가 발생할 수 있다.

따라서 이번 변경은 Broken Access Control 취약점 자체를 해결한 보안 패치가 아니라, 로그인 상태를 반영하도록 리뷰 수정 UI를 개선한 리팩터링으로 판단했다.
