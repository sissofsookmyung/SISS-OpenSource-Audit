## 🔍 변경 요약

`xmlattr`는 딕셔너리의 키와 값을 HTML 속성 문자열로 변환한다. 이전 구현에서는 속성 이름에 공백이 있는지만 검사했으므로 `/`, `>`, `=`가 포함된 키를 허용했다. 이러한 문자는 HTML 파서의 속성 이름 해석에 영향을 줄 수 있어, 공격자가 키를 제어하고 출력이 특정 HTML 문맥에 삽입되는 경우 XSS 위험이 있다.

### 핵심 코드 변경 (`src/jinja2/filters.py`)

```diff
-_space_re = re.compile(r"\s", flags=re.ASCII)
+_attr_key_re = re.compile(r"[\s/>=]", flags=re.ASCII)

-        if _space_re.search(key) is not None:
-            raise ValueError(f"Spaces are not allowed in attributes: '{key}'")
+        if _attr_key_re.search(key) is not None:
+            raise ValueError(f"Invalid character in attribute name: {key!r}")
         items.append(f'{escape(key)}="{escape(value)}"')
```

- `\s`: ASCII 공백 문자 검사
- `/`: 슬래시 검사
- `>`: 태그 종료 문자 검사
- `=`: 속성 이름/값 구분 문자 검사
- 부적절한 키가 발견되면 `ValueError`를 발생시켜 속성 문자열 생성을 중단한다.
- `escape(key)` 및 `escape(value)`는 그대로 유지됐다. **값의 HTML 이스케이프와 키의 유효성 검사는 별개의 방어**다.
- 함수 설명에는 사용자 입력을 속성 이름으로 사용하지 말고, 필요하면 별도 검증을 하라는 경고가 추가됐다.

### 테스트 변경 (`tests/test_filters.py`)

기존 공백 검사 테스트를 `@pytest.mark.parametrize("sep", ("\t", "\n", "\f", " ", "/", ">", "="))`를 사용하는 7개 입력 검증으로 확장했다. 각 입력에 대해 `ValueError`와 `Invalid character` 메시지를 확인한다.

## 🔐 보안 관점 분석

| 항목 | 패치 이전 (`d655030^`) | 패치 이후 (`d655030`) | 보안적 의미 |
|---|---|---|---|
| 속성 이름 검사 | `\s` | `[\s/>=]` | HTML 파싱에 영향을 주는 문자 차단 강화 |
| `class/name` | 허용 | `ValueError` | `/` 차단 |
| `class>name` | 허용 | `ValueError` | `>` 차단 |
| `class=name` | 허용 | `ValueError` | `=` 차단 |
| `class name` | `ValueError` | `ValueError` | 기존 공백 차단 유지 |
| 오류 메시지 | `Spaces are not allowed...` | `Invalid character in attribute name...` | 검사 범위 확장 반영 |

**취약점 원인:** 키를 HTML 속성 이름으로 직렬화할 때 HTML 파서의 구문 문자에 대한 검사가 불완전했다. `autoescape`로 속성 값을 이스케이프해도 키의 유효성 문제를 모두 해결할 수 없다.

**한계 및 주의:** 이번 재현은 잘못된 키의 허용/거부 동작을 검증한 것으로, 브라우저에서 스크립트 실행까지 재현한 것은 아니다. 패치 후에도 임의의 사용자 입력을 키로 허용하는 것은 안전하다고 단정할 수 없으므로 속성 이름에 대한 허용 목록 검증이 권장된다.

### 패치 전후 실제 동작 비교

동일한 `Environment(autoescape=True)` 및 `{{ {key: 'test'} | xmlattr }}` 템플릿으로 확인했다.

**패치 이전:**

```text
허용: 'class/name' ->  class/name="test"
허용: 'class>name' ->  class&gt;name="test"
허용: 'class=name' ->  class=name="test"
차단: 'class name' -> Spaces are not allowed in attributes: 'class name'
```

**패치 이후:**

```text
차단: 'class/name' -> Invalid character in attribute name: 'class/name'
차단: 'class>name' -> Invalid character in attribute name: 'class>name'
차단: 'class=name' -> Invalid character in attribute name: 'class=name'
차단: 'class name' -> Invalid character in attribute name: 'class name'
```

이번 패치는 HTML 속성 **값**을 이스케이프하는 것만으로는 속성 **이름**의 구문적 안전성을 보장할 수 없음을 보여준다. `xmlattr`의 키 검사 정규표현식을 확장해 잘못된 속성 이름을 거부하도록 했고, 로컬 환경에서 패치 전후 차이와 전체 851개 테스트 통과를 확인했다.
